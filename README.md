# Kitsu TV

Клієнт для Android TV — крок 6 із `../ARCHITECTURE.md`: пошук сервера, парування, каталог, плеєр.
Сервер уже вміє все, що телевізору треба (парування кодом, каталог, стрім із Range і перекодування,
прогрес на профіль), тож тут — тільки клієнт. Нативний: **Kotlin · Jetpack Compose for TV · Media3
(ExoPlayer)**, без DI-фреймворку.

```
TV/
├── app/                 Android-застосунок (Gradle-модуль)
├── design/              HTML-макети, з яких він намальований — див. нижче
├── gradle/, gradlew*    Gradle wrapper 8.10.2; AGP 8.7.3; Kotlin 2.0.21
└── local.properties     sdk.dir — локальний, у .gitignore
```

## Збірка

Потрібні JDK 17+ і Android SDK (platform 35, build-tools 35). На цій машині SDK стоїть у
`C:\Users\Ivan_Hontarenko\Android\sdk` (командні інструменти, без Android Studio) і записаний у
`local.properties`.

```bash
cd Kitsu/TV
JAVA_HOME='C:\Users\Ivan_Hontarenko\.jdks\corretto-21.0.5' ./gradlew :app:assembleDebug
# → app/build/outputs/apk/debug/app-debug.apk
```

⚠️ **У Git Bash `JAVA_HOME` має бути у Windows-формі** (`C:\…`, не `/c/…`), а `sdk.dir` — з
прямими слешами: AGP перевіряє обидва шляхи як Windows-шляхи, і Unix-форма падає з
*«The filename, directory name, or volume label syntax is incorrect»* ще на етапі
`compileDebugJavaWithJavac`, без жодного натяку на причину.

Встановити на телевізор:

```bash
adb connect <ip-телевізора>:5555      # «Налагодження через мережу» в налаштуваннях розробника
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

`release` підписується debug-ключем свідомо: це домашній застосунок, який ставиться через `adb`, а
не через магазин.

## Як він розмовляє з сервером

| Що | Маршрут | Заголовки |
|---|---|---|
| Хто це | `GET /api/v1/installation` | — (відкритий) |
| Код | `POST /api/v1/pairing/start` · `GET /api/v1/pairing/{id}` кожні 2 с | — (відкритий) |
| Сесія | `GET /api/v1/auth/session` · `POST /api/v1/auth/profile` | `Authorization: Bearer <token>` |
| Каталог | `GET /titles`, `/titles/{slug}`, `/credits`, `/seasons`, `/nodes?kind=genre` | + `X-Kitsu-Profile` |
| Файли | `GET /media?filter=m.work = '<slug>'` — ⚠️ не `/titles/{slug}/media`, якого на сервері більше немає | + `X-Kitsu-Profile` |
| Про сервер | `GET /server` — збірка, рантайм, фреймворки, усі бібліотеки з classpath | + `X-Kitsu-Profile` |
| Своє | `GET /me/progress`, `PUT /me/progress/{playKey}`, `/me/favourites` | + `X-Kitsu-Profile` |
| Відтворення | `GET /play/{playKey}` → квиток → `GET /stream/{ticket}` | квиток в адресі, без заголовків |

- **Токен пристрою** приходить один раз (`ADMITTED`) і лежить у DataStore (`kitsu-device`); разом із
  ним — адреса сервера і останній профіль. «Change server» стирає все, і парування починається наново.
- **Фільм грається за слагом**, серія — за `series-slug:s01e04` (як у `PlaybackService`/`EpisodeKey`).
  Прогрес ключується тим самим ключем, тож браузер і телевізор підхоплюють одне місце.
- **Direct play → transcode.** Спершу файл віддається як є (Range, перемотка байтами). Якщо декодер
  телевізора відмовляється (`onPlayerError`), плеєр просить `?quality=<найбільша з qualities>&start=<секунда>`
  — перекодування без довжини й без перемотки; перемотка там — новий запит із новим `start`, а позиція
  у фільмі = `start` + позиція плеєра. Що саме відбувається, завжди написано в кутку: `DIRECT PLAY` або
  `TRANSCODE · 1080p`.
- **Прогрес** — раз на 5 с під час відтворення, при виході, і `finished` наприкінці.

Сервер оголошує себе як `_kitsu._tcp` (JmDNS, `ServiceAnnouncer` у BE; вимикається `KITSU_DISCOVERY_ENABLED=false`),
і застосунок слухає саме це: назва з TXT `name`, версія з `version`, id — те, що телевізор запам'ятовує.
⚠️ Windows Firewall фільтрує за програмою — без inbound UDP 5353 для JVM бекенду список на телевізорі
лишиться порожнім; ручна адреса є завжди.

Фокус скрізь — `tv-material3 Surface` з одним `focusRing()`: 2dp освітленого акценту, 2dp **назовні**
краю + підйом 6%. Це те саме кільце, що в `design/tv.css`; жоден екран не малює власного.

⚠️ **Кільце пройшло три стани, і повертати попередній не треба.** Аквамарин до 2026-09-23 — зникав
на кнопці, залитій тим самим аквамарином. Майже біле до 2026-09-28 — це була єдина відповідь,
доступна Harbour, чий акцент сам був майже білим. Зараз це `Kitsu.accentText`, тобто акцент,
змішаний у бік білого, і малюється він **поза** контролем (`focusRingInset`), а не на ньому. Тому
на залитій кнопці кільце лежить поруч із заливкою: це інша геометрія, а не та сама помилка.

⚠️ **Палітра — точні значення `Kitsu/FE` (блок `.dark`), не окремий набір.** Причина розписана один
раз, у `design/tv.css` біля тих самих токенів — читати треба там, бо цей файл її лише згадує.

## Що змінилося з переходом на дизайн Kitsu (2026-09-28)

Harbour пішов; чотири його рішення скасовані свідомо, а не загублені:

| Harbour казав | Kitsu каже |
|---|---|
| кожен кут прямий, радіус 0 всюди | чотири радіуси — контрол 6, поверхня 8, медіа 10, діалог 12 (у dp) |
| рамка ахроматична, колір лише за стан | акцент — власний колір знака, і він позначає стан |
| кільце фокуса ахроматичне, ніколи не акцент | кільце — `accentText`, освітлений акцент, назовні контрола |
| нейтралі — справжні сірі | нейтралі — теплі майже-чорні |
| п'ять акцентів (lime · electric · violet · raspberry · mint) | дев'ять (ember — типовий, і це помаранчевий самого знака) |
| Golos Text + JetBrains Mono | **Inter** + JetBrains Mono |

⚠️ **Старі п'ять акцентів зникли, а не перейменовані.** Збережене ім'я з того набору не збігається
ні з чим, і `AccentStore` відкидає його на користь `Ember`.

⚠️ **Знак — одне креслення, `ui/components/BrandMark.kt`.** Ті самі три шляхи, що в
`Html/KitsuUI/logo.svg`, `Kitsu/FE/public/favicon.svg` і в браузерному `brand-mark.tsx`, повернуті
на +90°: різ крізь згин читається і як трикутник Play, і як плече K. Площини беруть токени
(`markFold` / `markBack` / `markFace`), а не градієнти файлу, бо в продукті знак іде за одним із
дев'яти акцентів. Іконка застосунку, банер Leanback і `BrandSpinner` — той самий набір шляхів.

⚠️ **`BrandSpinner` не крутиться.** Колір обходить три площини, геометрія не рухається: обертання
знищило б різ Play, заради якого знак і повернули. Він замінив дугу в `BusySpinner`, тож усі старі
виклики отримали його без переписування.

⚠️ **Привітальний екран (`SplashScreen`) — не екран завантаження.** Він живе фіксовані 1100 мс і
віддає керування, що б не робили ворота: сервер, який вимкнено, інакше тримав би чорну панель усі
свої тайм-аути. Ворітний стан `Loading` — це вже чесне «ще питаю», і там крутиться знак.

## Дизайн

`design/` — дев'ять HTML-макетів на 1920×1080, які ганяються стрілками в браузері, і `jmouse-uik.html`
— джерело правди для токенів і компонентів. Застосунок — їхній порт; коли вони розходяться, правильний
той, що в макеті, і в застосунку треба виправити.

⚠️ **Три екрани застосунку тепер не мають макета: `Collections`, `Genres` і вміст одного вузла**
(2026-09-23). Токени вони беруть ті самі — `design/tv.css` перефарбовано разом із застосунком ще раз
2026-09-28, разом із переходом на дизайн Kitsu, тож
дев'ять наявних макетів показують нову палітру самі, — але верстки цих трьох у `design/` немає, і
правило «правий той, що в макеті» на них поки не діє. Намалювати їх варто до наступної зміни цих
екранів, бо саме так набір макетів перестає бути джерелом правди: не одним рішенням, а трьома
відсутніми файлами.

```bash
cd design && npx http-server -p 5035 -s .     # http://localhost:5035/ — сторіборд
```

Клавіші в браузері: `← → ↑ ↓` D-pad · `Enter` OK · `Backspace`/`Esc` BACK · `1`…`4` стани екрана.

Десять рішень, за якими зроблено і макети, і застосунок: курсор — це фокус; нічого читабельного
менше за 22px (11sp); тільки темна тема; дек лишається, плеєр — єдиний екран без нього; ряди, не
сторінки; нічого не ховається за hover; ніякого набору, якого можна уникнути (код на ПК, PIN на панелі,
пошук сіткою); рішення про відтворення видно; мітка виду лише де види змішані; long-press OK не
використовується.

## Піджанри

Піджанр — це вузол виду `folder` під жанром: «Stephen King» усередині Horror. Не `collection`:
колекція належить **профілю**, тож полиця під жанром існувала б рівно для одного обличчя в домі, а
піджанр за визначенням домашній. `folder` не прив'язаний до профілю, дозволяє ручне наповнення,
вкладається без ліміту глибини і не має зовнішнього джерела — тому ресинк метаданих його не чіпає,
переписуючи жанри навколо.

У дереві для цього нічого нового не з'явилося: батьківський вид ніщо не обмежує, а перевірка
глибини рахує предків **того самого** виду. Браузер отримав екран для цього першим; телевізор їх
просто не бачив — через це кожен жанр тут виглядав пласким і мав інше число тайтлів, ніж той самий
жанр у браузері.

⚠️ **Полиця жанру — це жанр І ВСЕ, ЩО ПІД НИМ.** Фільм, залежаний тільки в «Stephen King», — це
фільм жахів, і полиця Horror без нього суперечила б дереву, яке хтось побудував.

⚠️ **Піддерево запитується по одному вузлу.** `nodeId` збігається лише з **прямим** членством, а
маршруту «і все нижче» на `/titles` немає — браузер обходить ту саму прогалину, розписуючи гілку
виразом jMQ по слагах. Тут її розписано запитами: по одному на місце, паралельно, злиття за
ідентифікатором. Жанр тримає кілька піджанрів, тож це кілька запитів, а не запит на рядок.

## Тайтли — профіль-специфічні

Каталог відповідає **залежно від того, хто питає**: кожен список на сервері прибирає тайтли з гілки,
яку цьому профілю не відкрито, а тайтл усередині такої гілки за власною адресою — це NOT FOUND, а не
просто відсутність на стіні.

Тому `Library` прив'язано ключем до ідентифікатора профілю. Без цього `rememberNavController` і
запам'ятовані рядки кожної стіни переживали б перемикання: телевізор повертався б із вибору профілю,
стоячи всередині жанру, якого новий профіль не може відкрити, показуючи чужі постери, і дізнавався б
про це лише через одне натискання.

⚠️ Ключ — саме **ідентифікатор профілю**, не сесія. Сесію замінює перевірка після будь-якого
втраченого запиту, і ключ на ній викидав би всю бібліотеку щоразу, коли 401 успішно відновлено.
